# Week 3 | Ops：准备项目介绍与用户测试

## 一句话项目介绍
一个能在 Monad 上监控多协议借贷仓位、识别可清算地址，并生成带 CLOB 价格校验的清算交易草稿的只读工具。

## 项目简介（100–200 字）
本项目针对 Monad 上 Aave / Euler / Morpho / Curvance 等借贷协议的高频清算场景：当前 keeper 和 operator 需要自行拼监控、模拟和价格路径，延迟高、链路不透明。我们做一个只读 + 模拟层：实时读取多协议健康因子，筛选可清算仓位，并生成一笔带 CLOB（Kuru / Perpl）价格校验的清算交易草稿，供 operator 审核后签名执行。全程不碰私钥、不广播真实交易，最小可用版本可在 10 分钟内完成部署和演示。

## 测试邀请文案
想试试在 Monad 上“一眼看到可清算仓位 + 一键拿到清算交易草稿”是什么体验吗？

我们做了一个只读原型：输入协议列表和健康因子阈值，它就会扫描 Aave / Euler / Morpho / Curvance 当前可清算地址，并给你返回一笔带 CLOB 价格校验的清算交易草稿（to / selector / value / calldata / 预估利润）。

全程只读，不碰你的私钥，也不会上链。约 10 分钟就能跑一遍并告诉我们哪里好用、哪里难用。

## 测试任务（让用户完成）
1. 打开项目 README：`C:\Users\gg\monad-liq-mvp`
2. 按 README 启动 Vercel API 或本地 `node api/index.ts`
3. 调用 `/scan?protocols=aave,euler&threshold=1.1`（或等价接口）
4. 观察返回：是否看到可清算地址列表、健康因子、以及一笔示例清算交易草稿
5. 把输出截图，并尝试改阈值再跑一次，对比结果差异

**最低门槛替代方案**：若本地 API 未就绪，可直接看 README 里的示例 JSON 输出截图，照样能完成反馈。

## 反馈问题（3–5 个）
1. 看完返回结果，你能说清这个工具“到底帮你做了什么”吗？（能 / 大概 / 不能，为什么？）
2. 可清算地址列表 + 交易草稿，对你评估是否值得执行清算有帮助吗？
3. 作为 operator 或 keeper，这个原型最让你困惑或卡住的地方是哪里？（比如看不懂 calldata、不知 profit 怎么算、想要自动 recurring）
4. 如果做成网页或聊天界面，你希望怎么使用它？（输入阈值和协议列表 / 按钮一键扫描 / 推送告警 / 其他）
5. 你愿意在真实 keeper 环境里执行一笔由该工具生成的交易草稿吗？为什么（信任 / 不信任 / 取决于什么）？
